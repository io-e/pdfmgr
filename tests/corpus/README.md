# Test corpus

The corpus has **50 PDF files**: the 8 original fixtures from `tests/Fixtures.cpp` and 42 files generated by `tests/Corpus.cpp`. None of them are checked in. They are generated in a temporary directory each time the tests run. This keeps the repository small, since the large files are a few MB, and it means the files are deterministic.

## Provenance and licence

Every file is synthesised by this project's own test code, so the corpus is covered by the project licence (AGPLv3). No third-party documents, images or fonts are used:

- Text is drawn with the standard 14 font Helvetica, which is not embedded.
- The "scanned" images are generated procedurally: noise plus bars that look like text.
- CJK text uses Adobe's predefined CMaps (`UniJIS-UCS2-H`, `UniGB-UCS2-H`, `UniKS-UCS2-H`) with **no embedded font**. Viewers substitute their own font. MuPDF uses its built-in fallback if the build includes one, otherwise the glyphs are blank. Arabic and Devanagari use `Identity-H` with a `ToUnicode` CMap and no embedded font. So no font licence applies. These files test parsing, text extraction, page operations and Unicode file names, not glyph shaping.
- Encryption, object streams and linearisation are written with the QPDF library (`QPDFWriter`). The malformed files are written byte by byte and never go through QPDF.

Fixture passwords are test data: user `user-pw`, owner `owner-pw`.

## Contents

| Category | Files | What it covers |
|---|---|---|
| base | 8 | Original fixtures: 1, 3 and 5 pages, landscape, Unicode file name (`é`), garbage (must fail cleanly), simple form, object streams |
| forms | 5 | AcroForm across several pages: text fields on 3 pages; checkbox and radio group; combo and list boxes; hierarchical field names on 4 pages; an `/XFA` packet next to the AcroForm fields |
| scanned | 5 | Image-only pages: 300 dpi grey, 600 dpi grey, 300 dpi RGB, 600 dpi 1-bit, and mixed 150/300/600 dpi in one file |
| encrypted | 5 | AES-256 with user and owner passwords; AES-256 owner-only; RC4-128 with user and owner passwords; RC4-40 owner-only; AES-128 user |
| large | 5 | 500 text pages; 200 image pages; 120 pages with object streams; 300 pages of mixed sizes; 150 pages sharing one image |
| unicode | 5 | Japanese (file name `unicode-日本語.pdf`), Chinese, Korean, Arabic (`unicode-عربي.pdf`), Hindi (`unicode-हिन्दी.pdf`) |
| sizes | 4 | A4, Letter, A3 and A5 in one file; 1 × 1 in; 200 × 200 in (the PDF maximum); MediaBox not at the origin, plus a CropBox |
| malformed | 4 | Wrong xref offsets; wrong `startxref`; dangling references to missing objects; wrong stream `/Length` |
| rotation | 4 | `/Rotate` 90, 180 and 270; inherited `/Rotate` plus `-90` |
| linearized | 3 | Linearised text, form and scan |
| minimal | 2 | One page with an empty content stream; one page with no `/Contents` and no `/Resources` |

The XFA file only checks that a document with an XFA packet still opens and that page operations keep it intact. The app does not render XFA forms.

## Test

`tests/test_corpus.cpp` is data-driven. For every file it does the following:
1. Opens the file. Files with a user password must first fail with `NeedsPassword`.
2. Checks the page count.
3. Renders the first, middle and last pages, scaled to about 400 px.
4. Checks the existing `/Rotate` values.
5. Rotates page 1 by 90° with QPDF.
6. Saves a copy, then reopens and renders it. Encrypted files must stay encrypted.

## Writing the corpus to disk

To test by hand, for example on Windows, write the corpus to a directory:

```
pdfcore_tests --write-corpus <dir>
```
